# Промт: починить боевую систему (игрок, враги, урон, фидбек)

Скопируй блок ниже в нового агента/сессию. Промт самодостаточен: в нём есть контекст,
инварианты, порядок работ и критерии приёмки.

## РОЛЬ

Ты — Unity/C# разработчик в проекте `DarkCrossoardOfDesteny` (Unity, PC-only, Input System,
URP, без мобильных ограничений). Твоя задача — довести боевую систему до состояния
«игрок понимает, что происходит, и ему есть зачем драться», не ломая существующие
системы культивации, инвентаря и UI.

## ГЛАВНАЯ ЦЕЛЬ

Сделать один предсказуемый контур боя:

```
ввод → анимация → окно хитбокса → попадание → урон → фидбек → смерть → награда
```

Сейчас контуров два (хитбокс для врагов, невидимая сфера для ресурсов), магия не наносит
урона, убийство ничего не даёт, смерть игрока мгновенная и тихая. Это надо исправить.

## ИНВАРИАНТЫ (не нарушать)

1. **Не переписывать системы культивации, инвентаря, UI и сохранений.** Меняй только
   боевые точки и минимально необходимые связки.
2. **PC-only, Input System.** Не добавлять мобильные контролы, не вводить legacy Input.
3. **Не добавлять новых пакетов.** Всё делать на существующих API Unity.
4. **Не ломать сцену `Game`.** Все новые ссылки — либо через `[SerializeField]` с
   авто-поиском в `Awake`, либо через существующий bootstrap.
5. **Не удалять legacy-файлы без явного разрешения.** Их можно пометить `[Obsolete]`,
   отключить в сцене или задокументировать. Удаление — отдельным шагом после подтверждения.
6. **Один источник урона на один клик.** После правок `PlayerInteraction` не должен
   наносить урон параллельно с `CombatHitbox`.
7. **Все новые публичные API — с XML-комментариями на русском**, в стиле проекта.
8. **Не трогать `Time.timeScale` вне `CombatFeedback`.** Пауза меню должна оставаться паузой.
9. **Не менять баланс культивации** (опыт, Ци, реалмы) без отдельного запроса.
10. **Проверять компиляцию после каждого слайса** и прогонять существующие EditMode-тесты.

## СЛАЙС 1 — данные и префаб (без изменения логики)

Цель: убрать ложь в ассетах, из-за которой числа и анимации не соответствуют задумке.

1. `Assets/Combat/Weapons/Fists.asset`, `Sword.asset`:
   - добавить поле `damage` (кулаки 8–10, меч 18–22);
   - проверить `useAnimationEvents` (должно быть `1`).
2. `Assets/Combat/Abilities/FistsJab.asset`, `SwordSlash.asset`, `MagicBurst.asset`:
   - заполнить `power` (FistsJab 12, SwordSlash 20, MagicBurst 25);
   - `MagicBurst`: задать `vfxPrefab` и `castAnimation` (подобрать из существующих
     VFX/анимаций проекта; если подходящего нет — создать простой префаб-заглушку
     и явно отметить это в отчёте);
   - решить вопрос доступности: либо снять `useRequiredDao` у `MagicBurst`,
     либо добавить Fire в `startingUnlockedDaos` в `CultivationConfig.asset`.
     Предпочтительно — снять требование для стартовой магии, Fire оставить для
     продвинутых техник.
3. `Assets/Player.prefab`: переключить `Animator.m_Controller` с
   `PlayerController.controller` на `PlayerCombat.controller`. Убедиться, что в сцене
   `Game` остался тот же контроллер (сейчас там override — он должен совпасть).
4. Комбо меча: в `PlayerCombat.controller` есть только `Sword Attack 1/2`, а
   `maxComboIndex` в сцене = 3. Выбери один вариант и выполни его:
   - **A (предпочтительно):** добавить `Sword Attack 3` (и при желании 4) с
     `CombatAnimationWindow` и тегом `Attack`;
   - **B:** добавить в `WeaponData` поле `maxComboIndex` и учитывать его в
     `PlayerController` при выборе длины комбо;
   - **C:** вернуть `maxComboIndex = 1` и явно ограничить меч двумя ударами.
5. `EnemyCombat_Strong` в `Game.unity`: сделать реально сильным (int 4, HP 200,
   урон 18) или переименовать в `EnemyCombat_2`. Не оставлять ложное имя.
6. Удалить мёртвый override `hitboxStart` у компонента `PlayerController` в `Game.unity`
   (такого поля у него нет).

**Проверка слайса:** в Play Mode меч и кулаки бьют с разным уроном; магия имеет VFX;
префаб игрока и сцена используют один контроллер; третий удар мечом проигрывает анимацию.

## СЛАЙС 2 — один контур урона

Цель: любой удар по любому объекту идёт через `CombatHitbox` → `IDamageable`.

1. `HarvestableObject`:
   - реализовать `IDamageable` (`IsDead`, `DamageRoot`, `TakeDamage(DamageInfo)`);
   - внутри `TakeDamage(DamageInfo)` вызвать существующую логику урона/смерти;
   - убрать `Debug.Log` на каждый удар (или спрятать под `#if UNITY_EDITOR` + флаг).
2. `PlayerInteraction`:
   - убрать нанесение урона из `AttackRoutine` (сферу/конус/`TakeDamage`);
   - оставить только проверки UI/лута/взаимодействия и, если нужно, поворот к цели;
   - убедиться, что клик по UI/луту по-прежнему не запускает атаку.
3. `AbilitySystem.CreateMagicHitbox`:
   - заменить «диагностическую» сферу на реальную зону урона:
     `Physics.OverlapSphere` (или `CombatHitbox` на временном объекте) →
     для каждого `IDamageable` (кроме владельца и своей команды) вызвать
     `TakeDamage(new DamageInfo(power * DamageMultiplier, owner, point))`;
   - одно попадание на цель за каст;
   - соблюдать `ICombatBlockable` (магию тоже можно блокировать, если так задумано;
     если нет — задокументировать решение);
   - VFX обязателен, время жизни зоны — из `AbilityData`.
4. `CombatHitbox`:
   - использовать `team`: не наносить урон цели той же команды;
   - для этого добавить в `IDamageable` (или отдельный интерфейс) свойство команды,
     реализовать его в `PlayerHealth`, `EnemyHealth`, `HarvestableObject` (Neutral);
   - починить `ImpactKind.Killed`: не полагаться на `target.IsDead` сразу после
     `TakeDamage` (смерть отложена). Варианты: добавить `bool WillDie` в `IDamageable`
     или пусть `EnemyHealth`/`HarvestableObject` сами публикуют `CombatEvents.Report`
     с `Kind = Killed` в момент смерти.
5. Убедиться, что `CombatFeedback.killEffect` реально срабатывает.

**Проверка слайса:** меч/кулаки бьют и врагов, и деревья/животных; урон не проходит
сквозь стены; два врага рядом не ранят друг друга; убийство проигрывает `killEffect`.

## СЛАЙС 3 — читаемость боя

Цель: игрок видит, что происходит, и различает «я попал» / «меня попали».

1. Полоса HP врага:
   - world-space Canvas (или SpriteRenderer) на префабе `EnemyCombat`;
   - подписка на `EnemyHealth.OnHealthChanged`, скрыта до первого урона;
   - не создавать по Canvas на каждого врага в `Update` — только при спавне/первом уроне.
2. Цвета цифр урона в `CombatFeedback`:
   - урон врагу — жёлтый/оранжевый;
   - урон игроку — красный;
   - блок — голубой «БЛОК».
   Для этого в `CombatImpact` уже есть `Victim`/`Attacker`; определи, кто игрок
   (например, по `PlayerHealth` на `Victim` или по тегу).
3. Фидбек получения урона игроком:
   - красная виньетка/вспышка (простой UI-Image с альфой) на `PlayerHealth.OnDamaged`;
   - мигание модели в i-frames (`SetInvulnerable`).
4. Звук:
   - минимум 4 события: замах, попадание, блок, смерть;
   - использовать существующий `SoundManager`, если он есть; иначе — `AudioSource.PlayOneShot`
     с сериализованными клипами;
   - не добавлять новые пакеты.
5. Убрать хит-стоп на урон по игроку, если он ощущается как рывок: оставить тряску,
   но не замедление (или сделать отдельный флаг).

**Проверка слайса:** у врага виден HP-бар; цифры разного цвета; при получении урона
игрок видит красную вспышку; есть звуки удара/блока/смерти.

## СЛАЙС 4 — смерть, награда, цикл

Цель: смерть и убийство должны быть событиями, а не «миганием».

1. Смерть игрока:
   - `PlayerRespawnService` не респавнит в том же кадре;
   - добавить задержку 1.5–2 с (анимация смерти/затемнение), затем респавн;
   - показать сообщение «Вы погибли» и «Потеряно X опыта» (использовать существующий UI-стиль);
   - после респавна — 3 с неуязвимости (уже есть) и, желательно, мигание.
2. Убийство врага:
   - лут: добавить `LootTable`/дроп в `EnemyHealth` или отдельный `EnemyLootDrop`,
     переиспользуя `WorldLootService`/`DropManager`;
   - опыт: начислить `CultivationSystem` опыт за убийство (не ломая медитацию);
   - эффект: `killEffect` из `CombatFeedback` + звук.
3. Респавн/количество врагов:
   - минимум 4–6 врагов в сцене или простой спавнер с точками;
   - не плодить тяжёлые `Update`-сканы.
4. Телеграф атаки врага:
   - вспышка/звук/индикатор за 0.2–0.3 с до открытия хитбокса;
   - не менять окна анимации без проверки в Play Mode.

**Проверка слайса:** смерть игрока — это последовательность с экраном и сообщением;
убийство врага даёт лут/опыт; врагов хватает на сессию.

## СЛАЙС 5 — глубина (опционально, если есть время)

1. Блок: стамина/прочность/чип-урон/слом блока + индикатор.
2. Разные комбо и урон у оружия; техники масштабируются от `power` и пассивов.
3. LOS-проверка для агро и ударов.
4. Убрать/пометить legacy: `EnemyAI`, `Enemy1`, `DestructibleObject`, `AttackHitbox`,
   старый `Weapon`-путь, неактивный объект `Enemy`.
5. Рамка цели/боевой лог (имя, HP, последние события).

## КРИТЕРИИ ПРИЁМКИ (проверить в Play Mode)

- [ ] Удар мечом по врагу: цифра, вспышка, хит-стоп, звук; HP-бар падает; 6–8 ударов до смерти.
- [ ] Удар кулаками слабее меча.
- [ ] Убийство: `killEffect`, лут/опыт, труп исчезает не мгновенно.
- [ ] Магия: видимый VFX, урон, цифры, убивает; Ци тратится осмысленно.
- [ ] Дерево/кабан получают урон тем же хитбоксом; нет урона сквозь стены/за спину.
- [ ] Удар врага по игроку: красная цифра, виньетка, тряска; блок — «БЛОК» и 0 урона.
- [ ] Два врага рядом не ранят друг друга.
- [ ] Смерть: задержка, экран/сообщение, потеря опыта, респавн на алтаре.
- [ ] В консоли нет спама на каждый удар.
- [ ] Префаб игрока и сцена используют `PlayerCombat.controller`.
- [ ] Существующие EditMode-тесты проходят (`CombatCrashSafetyTests`, `CombatFeedbackTests`,
      `PlayerCombatControllerTests`, `PlayerDeathTests`, `PlayerResponsivenessTests`).
