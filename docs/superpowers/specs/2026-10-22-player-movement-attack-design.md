# Игрок: движение и атака — дизайн

Дата: 2026-10-22
Статус: на согласовании

## Зачем

Персонаж в `Game` не анимируется и не атакует: нет анимаций ходьбы/стояния, клик по врагу либо не срабатывает, либо наносит урон без удара. Нужно, чтобы игрок нормально ходил (WASD) и бил кулаком по ЛКМ в сторону курсора.

## Что нашлось

- В сцене `Game` Animator игрока переопределён на `Assets/PlayerAnimations/PlayerController.controller` (GUID `d72ac30c17265054499cbbf60f69b7ee`). У него `Base Layer` с весом 0, а клипы и state machine behaviours ссылаются на отсутствующие GUID.
- В `Assets/Player.prefab` Animator ссылается на другой контроллер — `BaseMale.controller` (GUID `f551bf2e7708b274785462f5f80d25ff`), тоже с весом 0. Поэтому в `Dungeon 2.0` анимаций тоже нет.
- `PlayerController.UpdateAnimation()` не записывает `Speed` (строка закомментирована), поэтому даже рабочий Blend Tree не переключался бы.
- `PlayerInteraction` использует старый `Input`, обрабатывает и `GetMouseButtonDown(0)`, и `GetButtonDown("Fire1")` (двойное срабатывание), наносит урон мгновенным рейкастом на 50 м и не запускает анимацию.
- Подходящий Humanoid-набор: `Assets/Assets/HumanLowPoly/Art/Animations/Animations_Starter_Pack` — `Idle`, `Sprint`, `PunchRight` и др. Модель `BaseMale` тоже Humanoid, ретаргетинг возможен.

## Цели

- Idle/бег с анимацией при движении на WASD.
- ЛКМ (и gamepad West) — удар кулаком с анимацией, поворотом к курсору и уроном врагам вблизи.
- Один клик = один удар, без двойных срабатываний.
- Работает в `Game` и `Dungeon 2.0`.

## Не цели

- Комбо, тяжёлые атаки, блок, уклонения.
- Урон по игроку, ИИ врагов, UI, инвентарь.
- Замена модели или рига игрока.

## Анти-цели

- Не трогать `BaseMale.controller`: он используется в `Menu`.
- Не править сторонние FBX и их `.meta` (анимационные события не добавляем).
- Не добавлять новые Input Actions: используем существующий `PlayerControls.inputactions`.

## Подходы

### Контроллер

1. **Пересобрать `PlayerController.controller` на месте (выбран).** GUID сохраняется, сцена `Game` подхватывает его без правок. В префабе меняем ссылку на него, чтобы `Dungeon 2.0` унаследовал рабочий контроллер. Меньше всего правок ссылок, старый сломанный контроллер всё равно непригоден.
2. Создать новый контроллер и переподключить его в префабе и сцене `Game`. Чище по именам, но больше точек, где можно забыть ссылку.
3. Управлять анимацией из кода через Playables. Отброшено: сложнее поддерживать, нет нормального редактирования в Unity.

### Урон

- **A (выбран):** поворот к курсору, `PunchRight`, через 0.3 с — урон в конусе 2.5 м перед персонажем, кулдаун 0.7 с.
- B: Animation Event на клипе. Точнее, но требует правки чужого FBX и ломается при переимпорте.
- C: урон мгновенно по клику. Просто, но удар визуально не совпадает с попаданием.

## Решение

Вариант 1 + A.

### 1. Контроллер `PlayerController.controller`

- Параметры: `Speed` (Float), `Attack` (Trigger).
- Один слой `Base Layer`, `DefaultWeight = 1`.
- Стейт `Locomotion` (default): 1D Blend Tree по `Speed`, порог 0 — `Idle`, порог 1 — `Sprint`.
- Стейт `Attack`: клип `PunchRight`, `Speed = 1.25` (клип ~2 с, удар ~1.6 с).
- AnyState → `Attack` по триггеру `Attack`: без exit time, duration 0.1, `CanTransitionToSelf = 0`.
- `Attack` → `Locomotion`: exit time 0.92, duration 0.15, без условий.
- Клипы:
  - Idle: `{fileID: -6206981513316247533, guid: c346a9e2503cda64ba4698db6aa5e707, type: 3}`
  - Sprint: `{fileID: 7212731245373533189, guid: dcacd08f98af5794db5b56a6a66048e7, type: 3}`
  - PunchRight: `{fileID: 190365492218098281, guid: b4ed12fcea5716a4b88a664cf716cfc6, type: 3}`

### 2. `Player.prefab`

- У Animator заменить `m_Controller` с `f551bf2e7708b274785462f5f80d25ff` на `d72ac30c17265054499cbbf60f69b7ee`.
- `BaseMale.controller` не трогаем.

### 3. `PlayerController.cs`

- В `UpdateAnimation()` записывать `animator.SetFloat(speedParam, speed)`.
- Добавить `FaceTowards(Vector3 worldPoint, float duration)`: на время удара персонаж смотрит в точку удара, а не в сторону движения; по истечении — снова по движению.
- Добавить `PlayAttackAnimation()`: `animator.SetTrigger("Attack")`.

### 4. `PlayerInteraction.cs`

- Перейти на `PlayerControls` (Input System): подписка на `Attack.performed` в `OnEnable`, отписка в `OnDisable`.
- Убрать старый `Input` и двойной вызов.
- По атаке:
  - если кулдаун активен — игнор;
  - точка прицела: луч из камеры через позицию мыши до геометрии/земли; для геймпада — текущее направление движения или вперёд;
  - `PlayerController.FaceTowards(point, 0.45f)`, `PlayAttackAnimation()`;
  - через `hitDelay = 0.3` — `OverlapSphere` радиусом 2.5 м от точки перед игроком, фильтр по конусу `dot(forward, dir) >= 0.25`, урон каждому `IInteractable` один раз (через `GetComponentInParent`), точка попадания — ближайшая к игроку;
  - кулдаун 0.7 с.
- Сохранить `attackDamage`, гизмо радиуса.

### 5. Проверка

- Play mode в `Game`: Idle стоит, бежит и поворачивается на WASD; ЛКМ — удар в сторону курсора; враг получает урон один раз за клик; на бегу удар не «смотрит» в сторону движения.
- `Dungeon 2.0`: те же анимации через префаб.
- Нет ошибок компиляции и предупреждений Animator.

## Риски

- Качество ретаргетинга Humanoid-анимаций на `BaseMale` (пропорции/поза). Проверяю визуально; при проблемах подбираю другой клип или правлю аватар.
- Движение через `agent.velocity` может не работать, если игрок вне NavMesh. Проверяю в Play; при необходимости перехожу на `agent.Move` или `SetDestination`.
- Если Animator на корне не увидит кости вложенной модели, проверяю Avatar/перенос Animator на модель.

## Что остаётся на усмотрение исполнителя

- Точные длительности кулдауна и задержки удара (0.3/0.7 с) — подстрою по ощущениям после проверки.
- Форма конуса (сейчас ≈150°) и радиус 2.5 м.
- Скорость проигрывания PunchRight (1.25).
