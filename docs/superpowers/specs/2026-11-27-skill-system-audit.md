# Аудит системы скиллов (техники, пассивы, хотбар)

Дата: 2026-11-27
Охват: `Assets/Scripts/Cultivation/**`, `Assets/Scripts/Combat/{AbilitySystem,AbilityData,WeaponManager,PlayerHealth}.cs`,
`Assets/Scripts/UI/{AbilityBarUI,AbilitySlotUI}.cs`, `Assets/Scripts/UI/GameMenuController.cs`,
`Assets/Scripts/Legacy/UiManager.cs`, ассеты `Assets/Scripts/Cultivation/Data/**`,
`Assets/Combat/Items/**`, сцена `Assets/Scenes/Game.unity`.

Цель: описать, как система скиллов работает сейчас, и найти разрывы
пользовательского цикла «получить → открыть → назначить → применить → сохранить».

---

## 1. Краткий вывод

Каркас системы готов примерно на 80 %: есть данные техник, Дао-пути, реалмы,
два экрана скиллов, панель 1–5, мост в `AbilitySystem`, сохранение прогресса.
Но пользовательский цикл разорван в пяти местах:

1. **Пассивных скиллов нет в игровом контенте.** В коде их 10, в ассетах — 0.
   Вкладка «Пассивные» всегда пуста, `PassiveSkillService` всегда выдаёт множители 1.0.
2. **Пассивку нельзя получить.** «Выучено» ставится только свитком, а свиток в проекте
   один — на активную технику `sword_1`. Кнопки «Изучить» нет ни на одном экране.
3. **Магические техники не наносят урон врагам.** Зона магии — trigger с тегом
   `DammageObject`; на него реагирует только `DestructibleObject` (уничтожает объект).
   Враги получают урон только через `CombatHitbox`/`IDamageable`, которого у зоны нет.
4. **Сила техники (`TechniqueData.Power`) нигде не применяется.** Melee-техника бьёт
   уроном оружия, магия вообще не бьёт. Пассив «+10 % силы техник» тоже мёртв.
5. **Назначенные техники не сохраняются.** После перезапуска слоты 4–5 пустые;
   стартовая техника автоматически не выдаётся (методы `AutoRegisterStarterTechnique`
   и `AutoAssignStarterTechnique` написаны, но никогда не вызываются).

Плюс два системных UX-дефекта:

- экран «Скиллы» (Esc → «Техники») блокирует «Назначить» для невыученных техник,
  хотя экран «Техники» из панели культивации назначает их свободно — два экрана
  с противоположными правилами;
- при заблокированном касте (не тот Дао, мало Ци, не то оружие) игрок не получает
  никакого сообщения: событие `OnAbilityActivationBlocked` никто не слушает.

Минимальный MVP-фикс — 4 задачи (раздел 5, волна 0–2). Полный список — ниже.

## 2. Как система работает сейчас

### 2.1 Карта систем

```
Медитация (M)
  └─ CultivationSystem.AddExperienceQi / AddComprehension
  └─ DaoSystem.AddPoints(ActiveDao)  ──►  уровень Дао = f(очки), автоматически

DaoPath (SO) ── список TechniqueData (SO)
  │
  ├─ Активные / Block / Aura ──► TechniqueListUI / SkillListUI
  │                                   │ «В слот» / «Назначить»
  │                                   ▼
  │                        CultivationAbilityBridge
  │                         (TechniqueData → runtime AbilityData)
  │                                   ▼
  │                        AbilitySystem, слоты 4–5 (индексы 3–4)
  │                                   ▼
  │                        AbilityBarUI (клавиши 1–5)
  │                                   ▼
  │                   Melee: анимация + хитбокс оружия
  │                   Magic: временная trigger-зона с тегом DammageObject
  │
  └─ Passive ──► PassiveSkillService (только «выученные»)
                     └─ множители в PlayerHealth / QiComponent /
                        CultivationSystem / AbilitySystem / AlchemyService
```

Резервная ветка: если на игроке **нет** `AbilitySystem`, bootstrap включает
`CultivationCastController` + `CultivationQuickBarUI` (демо-каст на 1–5).
В `Game.unity` `AbilitySystem` есть, поэтому живёт основная ветка через мост,
а демо-каст сам себя отключает (`CheckExternalSystems`).

### 2.2 Данные

`TechniqueData` (`Assets/Scripts/Cultivation/Runtime/TechniqueData.cs`):

| Поле | Смысл | Где используется |
|---|---|---|
| `techniqueId` | строковый ID | ключ словаря выученных, `AbilityData.abilityId` |
| `daoType` | школа | требования, цвет, оружие, melee/magic |
| `kind` | Active / Passive / Aura / Block | только Passive реально влияет на логику |
| `rank` | ранг 1–3 | только отображается в UI |
| `requiredDaoLevel` | уровень Дао | проверка доступности |
| `requiredRealmIndex` | индекс реалма | проверка доступности |
| `qiCost` | стоимость Ци | списывается в `AbilitySystem.TryActivate` |
| `cooldown` | КД | `AbilitySystem.cooldownEnd` |
| `power` | «сила» (урон/лечение) | **не используется в живом пути** |
| `castAnimationClip` | клип замаха | `WeaponManager.PlayCastAnimation` |
| `vfxPrefab` | VFX | `AbilitySystem.SpawnVfx` |
| `passiveEffect` / `passiveValue` | пассив | `PassiveSkillService` |

`DaoPath` — цвет, макс. уровень, список техник. `DaoSystem` — уровни/очки/активный
Дао/выученные техники/разблокировка. Уровень не покупается: `AddPoints` сразу
пересчитывает `level = startingLevel + points / pointsPerLevel`.

`CultivationDefaults` — эталонный контент: 4 реалма × 3 ступени, 5 Дао,
15 активных техник + 10 пассивов.

### 2.3 Как игрок получает техники

1. Медитирует → получает очки активного Дао и опыт Ци.
2. Уровень Дао растёт автоматически (10 очков = 1 уровень).
3. Техника считается доступной, если `RequiredDaoLevel <= уровень Дао`
   и `RequiredRealmIndex <= текущий реалм` (`DaoSystem.IsTechniqueAvailable`).
4. **«Выучить»** можно только предметом-свитком: `CultivationItemBridge.ApplyScroll`
   → `DaoSystem.AddLearnedTechnique`. В контенте есть один свиток —
   `Scroll_SwordStrike` на `sword_1`.
5. Выученная техника обходит требования по уровню/реалму
   (`IsTechniqueAvailable` возвращает true, если `HasLearnedTechnique`).

Итог: для активных техник «изучение» — необязательный ярлык. Для пассивов —
единственный способ активации, но свитков пассивов нет.

### 2.4 Как техника попадает в бой

`CultivationBootstrap.SetupTechniqueOutput`:

- если на игроке есть `AbilitySystem` → создаётся `CultivationAbilityBridge`,
  `TechniqueData` конвертируется в runtime `AbilityData`
  (`HideFlags.DontSave`), кладётся в первый свободный слот 4–5;
- иначе → `CultivationCastController` (демо).

`AbilitySystem`:

- слоты 1–3 — способности оружия (`WeaponData.abilities`);
- слоты 4–5 — техники Дао (приоритетно, «поверх магии»);
- `ValidateCultivation`: Дао открыт, **активный Дао совпадает** с Дао техники,
  уровень Дао, реалм, Ци;
- `TryActivate`: списывает Ци, ставит КД, запускает корутину;
- Melee: `WeaponManager.PlayCastAnimation` + штатный хитбокс оружия;
- Magic: VFX + временная сфера-триггер с тегом `DammageObject`.

### 2.5 UI

| Экран | Откуда | Что умеет |
|---|---|---|
| `TechniqueListUI` | панель культивации → «Техники» | сетка карточек, фильтр по Дао, «В слот» (по доступности) |
| `SkillListUI` | Esc → «Техники» (`GameMenuController.OpenSkills`) | вкладки «Техники»/«Пассивные», статусы, «Назначить» (только если выучено) |
| `AbilityBarUI` | сцена, всегда | 5 слотов, КД, стоимость Ци, бейдж Дао, клик = каст |
| `CultivationQuickBarUI` | только демо-ветка | панель 1–5 для `CultivationCastController` |

### 2.6 Сохранение

`CultivationStateCache` (PlayerPrefs, `Cultivation.Save.v2`) хранит реалм, ступень,
опыт, Прозрение, Ци, активный Дао, маску открытых Дао, уровни/очки, **ID выученных
техник**, дебафы, HP, грейд алхимии. Назначенные в слоты техники **не хранятся**.

### 2.7 Фактический контент в ассетах

| Что | В коде (`CultivationDefaults`) | В ассетах (игра) |
|---|---|---|
| Активные техники | 15 | 15 |
| Пассивы | 10 | **0** |
| Дао-пути | 5 | 5, но в каждом только 3 техники |
| Свитки техник | — | 1 (`sword_1`) |
| Семена Дао | — | 1 (`Fire`) |
| Иконки техник | — | 0 (все `null`) |

Ассеты устарели: `CultivationSetup` умеет создавать пассивы
(`GetTechniques` возвращает и их), но `Tools → Cultivation → Setup Test Assets`
после добавления пассивов не запускали. `Validate Setup` проверяет только
«≥ 3 техник на путь», поэтому проблему не видит.

## 3. Что видит игрок: сценарий первого запуска

1. Запускает `Game.unity`. Bootstrap находит игрока, добавляет компоненты,
   грузит `CultivationConfig.asset` (15 техник).
2. Открывает Tab → «Техники». Видит 15 карточек. Доступны только `sword_1`
   и `fist_1` (стартовые Дао 1 уровня, реалм 0).
3. Жмёт «В слот» у `sword_1` → техника уходит в слот 4. Хотбар показывает
   цветной прямоугольник без иконки и без названия.
4. Жмёт 4 → каст идёт, Ци тратится, КД тикает. Урон = урон оружия (кулаки 12),
   а не `Power = 35`.
5. Назначает `fist_1` в слот 5. Жмёт 5 → ничего: активный Дао — Меч, а техника
   требует Кулак. Сообщения нет, слот просто приглушён.
6. Открывает Esc → «Техники» (экран «Скиллы»). У `sword_1` кнопка «Назначить»
   активна только если техника «выучена»; выучен только `sword_1` (свиток),
   поэтому у остальных кнопка навсегда серая.
7. Открывает вкладку «Пассивные» — пусто.
8. Перезапускает Play mode — слоты 4–5 пустые, назначать нужно заново.
9. Пробует огненный шар (после семени Огня и смены Дао у алтаря) — VFX есть,
   враг не получает урона.

Это и есть основные пользовательские разрывы.

## 4. Находки

Приоритеты: **P0** — ломает основной цикл, **P1** — сильно мешает/вводит
в заблуждение, **P2** — полировка и техдолг.

### P0

| ID | Находка | Доказательство | Влияние |
|---|---|---|---|
| S-01 | Пассивов нет в ассетах | нет `Technique_*_passive_*.asset`; в `Dao_*.asset` по 3 техники; `passiveEffect` не встречается ни в одном `.asset` | вкладка «Пассивные» пуста, пассивы не работают |
| S-02 | Пассивку нельзя получить | `AddLearnedTechnique` вызывается только из `CultivationItemBridge.ApplyScroll`; свитков пассивов нет; кнопки «Изучить» нет | весь пассивный слой недостижим |

## 5. Что и как исправить

### Волна 0. Контент и «честные» пассивы (P0, ~0.5 дня)

1. **Пересоздать ассеты.** Запустить `Tools → Cultivation → Setup Test Assets`.
   Ожидание: 25 `Technique_*.asset`, в каждом `Dao_*.asset` по 5–6 техник,
   в том числе пассивы. Проверить `Dao_Sword.asset` (должен содержать
   `Technique_sword_passive_1/2`).
2. **Сделать пассивы доступными по прогрессу, а не по свитку.**
   В `PassiveSkillService.TryAdd` считать пассив активным, если выполнены
   требования (`RequiredDaoLevel`, `RequiredRealmIndex`), а «выучен» — это
   дополнительный обход требований. Это соответствует заявлению
   «пассивки школы открываются по уровню Дао» и убирает зависимость от
   несуществующих свитков.
   Альтернатива (если свитки обязательны): добавить 10 свитков пассивов в лут
   и кнопку «Изучить». Дороже по контенту, но сохраняет «коллекционирование».
3. **Починить `Validate Setup`:** проверять, что на каждый Дао есть пассив,
   что всего техник ≥ 20, что у пассивов `passiveValue > 0`.
4. **Обновить README** (`Assets/Scripts/Cultivation/README.md`): убрать
   неверное «слот 1 занят», описать реальный старт и вкладку «Пассивные».
5. **Сразу закрыть побочный эффект.** После появления пассивов в ассетах
   `TechniqueListUI` начнёт показывать их в сетке с кнопкой «В слот»,
   а `CultivationAbilityBridge` откажет («пассивная техника, в слот не кладётся»).
   Отфильтровать пассивы в `TechniqueListUI` (или показать их без кнопки
   назначения). В `AutoRegisterStarterTechnique` брать первую **непассивную**
   доступную технику.

### Волна 1. Боевая корректность (P0, ~1 день)

1. **Магия должна бить.** В `AbilitySystem.CreateMagicHitbox`:
   - добавить на зону `CombatHitbox`, `Configure(power * DamageMultiplier, CombatTeam.Player, ownerRoot)`,
     `SetActive(true)`, `targetLayers = ability.damageLayers`;
   - оставить тег `DammageObject` для разрушаемых пропов;
   - уничтожать зону через `magicHitboxLifetime`.
   `CombatHitbox` уже игнорирует владельца и не бьёт одну цель дважды.
2. **Melee должен использовать `Power`.**
   - добавить в `WeaponManager` метод `SetDamageOverride(float? damage)` или
     в `CombatHitbox` поле `DamageOverride`;
   - в `AbilitySystem.ExecuteMelee` перед атакой выставить
     `damage = technique.Power > 0 ? technique.Power * DamageMultiplier : null`,
     после каста — снять;
   - `Power = 0` (Block) оставляет урон оружия.
3. **Применить `DamageMultiplier`** к обеим веткам. После этого пассив
   «+10 % силы техник» начнёт работать.
4. **Вернуть Ци при провале каста.** Если `PlayCastAnimation` вернул false —
   `qi.Restore(cost)`, КД не ставить (или ставить 0).
5. **`MeleeDamagePercent`:** добавить множитель в `WeaponManager`/`CombatHitbox`
   (например, `PlayerDamageMultiplier`), который читает
   `PassiveSkillService.GetMultiplier(MeleeDamagePercent)`. Без этого пассив
   остаётся мёртвым.
6. **Block/Aura:** на MVP — либо реализовать минимально
   (Aura = временный бафф с длительностью, Block = `PlayerBlockController`
   на N секунд), либо честно скрыть из назначаемых и подписать
   «механика в разработке». Не оставлять кнопку, которая обещает одно,
   а делает обычный удар.

### Волна 2. Слоты, сохранение, обратная связь (P0/P1, ~1–1.5 дня)

1. **Сохранение хотбара.** `CultivationSnapshot` v3:
   `string[] techniqueSlotIds = new string[2]` (индекс = слот 4/5).
   `Capture` — из `CultivationAbilityBridge` (передать его в `Capture`),

## 6. Критерии приёмки (глазами игрока)

1. Первый запуск: в слоте 4 стоит «Удар клинка». Клавиша 4 кастует, тратит Ци,
   наносит урон врагу, запускает КД.
2. «Огненный шар» (после открытия Огня и смены Дао у алтаря) наносит урон
   врагу на дистанции, а не только рисует VFX.
3. «Удар клинка» (`Power 35`) бьёт заметно сильнее базовых кулаков (`12`).
4. Вкладка «Пассивные» показывает 10 пассивов со статусами. При Дао 3 + реалм 1
   пассив активируется, и цифры HP/Ци/урона в UI меняются.
5. Назначение в слот 4/5 явное; «Снять» работает; после перезапуска
   назначения на месте.
6. Попытка каста техники чужого Дао даёт понятное сообщение, слот приглушён,
   в tooltip написано, какой Дао нужен.
7. Нельзя случайно потерять технику: занятый слот требует замены,
   повторное назначение не переносит её молча.
8. Экран «Скиллы» и «Техники» из панели культивации показывают одни и те же
   данные и правила.
9. Esc → «Культивация» открывает панель.
10. В консоли нет ошибок и предупреждений `[Cultivation]`/`[AbilitySystem]`
    на штатном сценарии.

## 7. Риски и ограничения

- **Не ломать инвентарь, экипировку, лут, оружие и хитбоксы.** Все правки —
  аддитивные: новые методы/подписки, без изменения сигнатур существующих
  публичных API, кроме явно перечисленных.
- **Регенерация ассетов** (`Setup Test Assets`) перезаписывает поля конфига
  (`canSwitchAnywhere`, стартовые Дао и т.п.). Это ожидаемо, но нужно
  предупредить и проверить диффом.
- **Сохранение v2 → v3.** Старый JSON должен читаться: отсутствующие поля —
  значения по умолчанию, слоты пустые, игра не падает.
- **Магический урон и слои.** `CombatHitbox.targetLayers` по умолчанию `~0`;
  нужно прокинуть `AbilityData.damageLayers`, иначе зона заденет владельца
  (защита — `OwnerRoot`) или триггеры.
- **VFX-зона живёт 0.2 с** (`magicHitboxLifetime`); при добавлении
  `CombatHitbox` с `FixedUpdate`-фолбэком нужно убедиться, что один каст
  не бьёт дважды (в `CombatHitbox` есть `hitTargets`).
- **Aura/Block** — это отдельный дизайн; в MVP лучше скрыть, чем имитировать.
